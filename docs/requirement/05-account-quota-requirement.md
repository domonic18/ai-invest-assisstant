# 账号准入与 AI 用量治理 需求文档

> 版本：V1.0（2026-09-13 定稿）　状态：待排期
> 本文档为独立需求，功能域编号 `F-ACCT`；与既有设施（用户体系、认证、`llm_config`、助手 Agent、API-KEY/MCP、后台管理）的衔接在 §2 逐项说明，不改动既有需求文档；其中与 01 文档 F-USER-03「模型配置」的口径冲突（回退策略）在 §2 与 F-ACCT-04 显式声明以本文档为准
> 原型：待制作（定稿后排期补充注册审批流与个人配额页原型，登记进 docs/prototypes/ 索引）

## 1. 文档概述

### 1.1 背景与目的

系统即将部署到公网。当前存在两个治理缺口：

1. **注册即用**：`/auth/register` 成功后立即发放登录凭证（201 + AuthResponse），任何陌生人注册即可使用全部功能
2. **AI 成本不可控**：全部 AI 能力（助手对话、页面 AI 生成、API-KEY/MCP 调用）统一走系统预置模型（`llm_config`），无 token 用量计量、无预算上限——系统 API 费用会随公网用户增长失控

本文档定义三个相互配合的治理能力：

- **F-ACCT-01 注册审批准入**：新用户提交注册申请后，须管理员审批通过方可登录使用，公网环境下把住"谁能用"
- **F-ACCT-02/03 Token 计量与配额**：系统预置模型调用逐次精确计量 token；新用户获得一次性总量配额（默认 100,000 tokens，可配），耗尽后 AI 功能不可再用系统模型——把住"能用多少"
- **F-ACCT-04 自备 API Key（BYOK）**：用户可在个人设置配置自有 API Key，配置生效后 AI 功能完全走自有 Key 调用（不占配额、不计系统成本）；调用失败直接报错、不回退系统模型——给重度用户留出合规出口

### 1.2 适用范围与用户

- **普通用户**：提交注册申请、查看个人配额与消耗、配置/清除自备 Key
- **管理员**：审批注册申请、调整配额、查看用量运营看板
- **系统链路**：模型调用封装层增加统一计量埋点
- **不涉及**：付费/充值/套餐体系；按月重置配额；多模型分别设配额

### 1.3 术语表

| 术语 | 含义 |
|------|------|
| 注册申请 | 新用户提交的账号开通请求，含用户名/邮箱/密码 + 可选申请说明；提交后处于待审状态，不发放登录凭证 |
| 账号状态 | `pending`（待审）→ `approved`（可用）/ `rejected`（驳回，附原因）；`is_active` 保留原有语义（管理员禁用），与审批状态正交 |
| 系统模型 | `llm_config` 表配置、由平台付费的预置 LLM |
| BYOK | Bring Your Own Key，用户在个人设置配置的自备 API Key（协议/base_url/模型名/密钥） |
| Token 用量 | 单次模型调用的 prompt_tokens + completion_tokens；流式响应优先取协议 usage 块真实值，无 usage 的模型按 tokenizer 估算并标注 `estimated` |
| 配额 | 用户使用系统模型的一次性 token 总量（跨 AI 功能共享），只减不重置，管理员可调整追加 |
| 预扣 | AI 请求开始时按预估 prompt tokens 预先扣减配额、结束后按实际用量结算的机制，防止并发超支 |

## 2. 既有设施与衔接点（2026-09-13 实证）

| 既有设施 | 现状 | 本需求如何衔接 |
|----------|------|----------------|
| `user` 表 | 仅 `role`（user/admin）+ `is_active`，无审批状态 | 新增 `status`（pending/approved/rejected）+ `application_note`/`reject_reason`；存量用户迁移即 `approved` |
| `/auth/register` | 注册成功立即发登录凭证 | 改为提交申请：201 返回"已提交待审批"，不发 token；登录时按 status 拦截 |
| 登录链路 | 仅校验密码与 `is_active` | 增加 status 校验：pending 提示等待审批，rejected 提示未通过（附原因） |
| `llm_config` + `model_factory` | 系统级唯一模型出口，无用途维度、无用量记录 | 计量埋点在模型调用封装层统一拦截（助手/页面/API-KEY/MCP 共用同一出口）；BYOK 作为并行出口接入工厂 |
| 01 文档 F-USER-03「模型配置」 | **尚未实现**；原设计含"用户模型不可用时自动回退系统默认模型" | 该回退语义与预算控制冲突，**本文档重定为不回退、直接报错**；F-USER-03 实施时按本文档口径执行 |
| F-API-01 API-KEY/MCP | 用户 API-KEY 调用平台 AI 能力 | 该路径计入调用者配额（走系统模型时） |
| AI 交互范式 | 页面 AI 生成统一走侧边栏 Agent（助手会话），定时任务走 Celery internal | 计量按"会话属主用户"归集；定时任务属系统成本，归入"系统"维度，不占个人配额 |
| 后台 F-ADMIN-01 用户管理 | 已有启用/禁用、角色设置 | 扩展：待审队列、审批操作、配额调整、用量视图 |

**能力缺口（全部为本需求新增）**：账号状态与审批流、登录按状态拦截、token 用量计量表与埋点、配额存储/预扣/拦截、用户自备 Key 配置与模型出口分流、管理端用量看板。

## 3. 用户场景

| 场景 | 角色 | 描述 | 频次 |
|------|------|------|------|
| 注册申请 | 新用户 | 提交用户名/邮箱/密码 + 简短申请说明，得到"待审批"回执，等待开通 | 一次性 |
| 日常审批 | 管理员 | 后台待审列表逐条处理：通过（可设初始配额）/ 驳回（必填原因）；有新申请时后台角标提醒 | 事件驱动 |
| 用量感知 | 普通用户 | 个人设置页看剩余配额与消耗明细；临近耗尽（<10%）与耗尽时收到明确提示 | 日常 |
| 配额耗尽 | 普通用户 | AI 功能被拦截并引导"配置自有 Key 或联系管理员"；行情/资讯等非 AI 功能不受影响 | 事件驱动 |
| 自备 Key | 重度用户 | 个人设置配置自有 API Key（连通性测试通过后生效），此后 AI 全走自有 Key，配额不再下降 | 低频 |
| 预算运营 | 管理员 | 用量看板盯全站 token 消耗趋势、Top 用户、按功能/模型分布；按需调整个别用户配额 | 每周 |

## 4. 总体设计

**账号生命周期**：

```
注册提交 → pending ──管理员通过──▶ approved ──（可被 is_active 禁用）──▶ 使用中
              └──管理员驳回（附原因）──▶ rejected（不可登录，可另邮箱重新申请）
存量用户：迁移直接 approved
```

**AI 调用决策流（每次用户触发的 AI 请求前置执行）**：

```
用户触发 AI（助手对话 / 页面生成 / API-KEY·MCP）
  ├─ 已配置生效的自备 Key？ ──是──▶ 走自有 Key 调用（不检查配额、不计量入系统、失败直接报错）
  └─ 否 ──▶ 检查系统模型剩余配额
              ├─ 不足 ──▶ 拦截：明确错误 + 引导（配自有 Key / 联系管理员）
              └─ 足够 ──▶ 预扣预估量 ──▶ 调用系统模型 ──▶ 按实际 usage 结算并记录用量
定时 AI 任务（Celery internal）─▶ 系统维度计量，不占个人配额
```

## 5. 功能需求

### 5.1 F-ACCT-01 注册申请与审批

- **描述**：
  - **注册改申请**：注册表单增加可选"申请说明"；提交成功返回待审批回执页（不发登录凭证）；同一用户名/邮箱有待审申请时提示"已有申请在审"，不重复建号
  - **登录拦截**：`pending` → "账号待审批，请等待管理员开通"；`rejected` → "申请未通过"+ 管理员附的原因
  - **管理员审批台**（后台用户管理扩展）：待审队列（申请时间、用户名/邮箱、申请说明），逐条「通过（可设初始配额，默认取全局值）/ 驳回（必填原因）」；新申请产生后台角标提醒；全部审批操作入审计日志
- **关键规则**：
  - 存量用户迁移一次性全部置 `approved`，无感升级
  - 注册接口按 IP 限流；`pending` 申请超期（默认 30 天，可配）自动过期清理
  - `rejected` 用户名/邮箱不永久占位，允许清理后重新申请

### 5.2 F-ACCT-02 Token 用量计量

- **描述**：模型调用封装层统一埋点，逐次记录：用户、触发功能（助手对话/页面生成/API-KEY·MCP/系统任务）、模型、出口（系统模型/自备 Key）、prompt/completion/total tokens、`estimated` 标志、时间
- **计量范围（已确认口径）**：
  - **计入个人配额**：助手对话（含多步 Agent 全部工具调用轮次）、页面手动触发的 AI 生成、用户 API-KEY/MCP 的 AI 调用——均按会话/凭证属主归集
  - **不计入个人**：系统定时 AI 任务（系统成本，单独归"系统"维度）；自备 Key 调用（仅统计不占配额）
- **关键规则**：
  - 流式响应优先从协议 usage 块取真实值；不返回 usage 的模型按 tokenizer 估算并标注，看板展示 estimated 占比
  - 计量写入失败不得影响主请求结果（降级记日志，异步补偿写入）
- **数据**：新表 `user_token_usage`（逐次明细）；用户个人页展示剩余配额与消耗明细（按功能分组）；幂等 SQL 迁移

### 5.3 F-ACCT-03 系统模型配额控制

- **描述**：新用户审批通过时获得一次性总量配额（全局默认 100,000 tokens，可配）；系统模型出口前置配额检查，耗尽即拦截
- **关键规则**：
  - **拦截范围**：配额耗尽后，走系统模型的 AI 功能（助手对话/页面生成/API-KEY·MCP AI 调用）统一返回明确错误码与引导文案（配置自有 Key / 联系管理员追加）；**非 AI 功能（行情、资讯、知识库检索、图表等）不受任何影响**
  - **预扣与结算**：请求开始按预估 prompt tokens 预扣（Redis 原子操作），完成后按实际总量结算回补差额，防止并发超支
  - **admin 角色**：默认不设上限（豁免可配），但仍计量统计，保证看板全量透明
  - 管理员可按用户调整：追加/核减、重置为全局默认

### 5.4 F-ACCT-04 用户自备 API Key（BYOK）

- **描述**：个人设置页「我的模型」配置：协议（openai / anthropic 兼容）、base_url、model_name、api_key；保存前提供**连通性测试**（发送极小请求验证）；保存后对本人所有 AI 功能生效，也可随时清除恢复系统模型（此后受配额约束）
- **关键规则**：
  - **安全**：api_key 以 Fernet 认证加密落库（复用 `llm_config` 同一加密路径 `app/utils/crypto.py`）；前端脱敏展示（前 4 后 4）；后端日志自动过滤 api_key 字段（对齐 F-USER-03 既有安全设计）
  - **生效范围（已确认口径）**：助手对话 + 页面手动 AI 生成 + API-KEY/MCP 调用**全部走自有 Key**，与系统功能同提示词同能力，仅模型出口不同；不占配额、不计系统成本
  - **失败策略（已确认口径，覆盖 F-USER-03 原设计）**：自有 Key 调用失败（无效/欠费/限流）**不回退系统模型**，直接报错并指引用户检查 Key 配置——杜绝静默烧系统预算
  - 同一时间仅一套生效配置；清除配置立即回落系统模型

### 5.5 F-ACCT-05 管理端配额与用量运营

- **描述**：
  - 用户列表扩展列：账号状态（待审/正常/禁用/驳回）、剩余配额、累计消耗、是否自备 Key；行内操作：审批、调整配额、查看消耗明细
  - 全站用量看板：日/周消耗趋势、消耗 Top 用户、按功能（助手/页面/API-KEY·MCP/系统任务）与按模型分布、estimated 占比、配额耗尽用户数
  - 全局设置：默认配额值、pending 过期天数、admin 豁免开关
- **权限**：全部 admin 角色；审计日志记录配额调整与审批操作

## 6. 非功能需求

| 项 | 要求 |
|----|------|
| 权限 | 审批、配额调整、用量看板限 admin；自备 Key 与个人配额页仅本人可访问 |
| 安全 | api_key 加密存储/脱敏展示/日志过滤；注册接口 IP 限流；审批与配额操作全量审计 |
| 计量准确性 | 真实 usage 优先、估算显式标注；计量链路故障降级不阻断业务；预扣+结算保证配额不超支 |
| 性能 | 配额检查为 AI 调用前置步骤，开销 <10ms（配额缓存 + Redis 原子预扣）；用量明细异步批量落库 |
| 时区 | 看板统计周期按北京时间（Asia/Shanghai）聚合；时间戳 aware UTC |
| 兼容 | 存量用户无感迁移（approved + 默认配额）；非 AI 功能零影响；API 契约变更（注册响应语义）在 shared/types 同步 |

## 7. 功能边界

**包含**：注册申请与审批流、登录状态拦截、token 用量计量（助手/页面/API-KEY·MCP/系统任务四类）、一次性配额与耗尽拦截（预扣结算）、用户自备 Key 配置与模型出口分流（失败不回退）、管理端审批/配额调整/用量看板
**不包含**：付费充值与套餐；按月重置或多模型分池配额；定时任务计入个人配额；静默回退系统模型（明确排除）；注册验证码/邮箱验证（可另行立项）；管理员配额豁免外的多级角色配额策略
