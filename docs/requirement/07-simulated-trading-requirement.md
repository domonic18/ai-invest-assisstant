## 1. 文档概述

### 1.1 背景与目的

平台的长期目标是沉淀**会自己进步的交易智能体**。交易方法论天然分风格——短线交易与中长线交易的选股、持仓周期、纪律完全不同，知识库中两类技能知识并存；若合并为单一智能体，两类纪律会互相污染。因此采用**多智能体架构**：

- **按风格分智能体**：首批两个独立智能体——**短线智能体**与**中长线智能体**，各自像一位风格鲜明的交易员
- **共享知识库、独立成长**：两者共用同一知识库（F-KB），但方法论提炼按各自风格的知识域进行；技能、记忆、交易记录、复盘完全隔离，互不污染
- **像人一样交易**：每个智能体盘后复盘当日并形成次日交易意图；次日盘中按人类交易员的注意力节奏**周期唤醒**（开盘/尾盘高频、中段低频、午休不唤醒），每次唤醒实时看盘面、按方法论思考判断、自主决定执行交易或不动；突发异动即时唤醒；熔断与硬止损由引擎兜底
- **交易全留痕**：委托、成交、交割单，以及**决策记录**（为什么买/卖/不动、依据什么）按智能体全量落库
- **定期学习**：各智能体独立进行每日增量复盘 + 每周综合学习，强化做对的、修正做差的，持续完善各自方法论
- **技能成为系统资产**：各智能体的方法论随时间版本化沉淀，可对比、可回滚、可治理；**跨智能体绩效对比**（短线 vs 中长线）天然形成风格间的对照实验

本需求为这一闭环提供三块底座：**虚拟交易训练场**（多账户撮合环境，一期）、**交易智能体**（盘中自主决策的每日循环，二期）、**自学习进化**（各自复盘→方法论迭代→版本沉淀→绩效验证，三期）。

**测试与公平性定位**：模拟盘的一切约束必须**在引擎层强制**（T+1、涨跌停、成交价裁定、护栏），而非依赖智能体提示词自觉。开发与验收阶段提供**人工测试交易通道**——人以管理员身份在独立测试账户实际操作，走与智能体完全相同的委托-撮合-交割链路：既验收撮合引擎正确性，也通过「人工尝试违规必被同样拦截」证明智能体没有作弊空间（详见 §4.3、F-SIM-14）。

> 术语澄清：本需求所称「强化学习」指「复盘反思 → 技能/方法论修订 → 版本沉淀 → 后续绩效验证」的经验进化闭环（LLM 反思式学习），不涉及梯度类策略优化。学习信号以**决策质量**为核心而非单笔盈亏——好决策可能亏钱、坏决策可能赚钱，复盘对照的是决策过程与纪律遵守。

### 1.2 适用范围与用户

- **交易主体**：多个系统级交易智能体，架构按 N 个设计；**首批两个**——短线智能体、中长线智能体，各对应一个独立模拟账户（独立初始资金、独立核算）；另有**人工测试账户**（管理员专用，见 F-SIM-14）
- **人的角色**：
  - 普通登录用户：**纯观测**——按智能体切换查看资产/持仓/计划/决策流水/交割/复盘总结，个股 K 线回看买卖点（标记按智能体区分）；**无任何交易入口**
  - 管理员：观测 + **治理 + 测试**——智能体生命周期管理（创建/启停）、各智能体方法论版本查看/编辑/审批/回滚/停用、风控护栏画像与唤醒时刻表配置、提炼与学习任务触发、运行监控；以及**人工测试交易**（独立测试账户手动下单，验证引擎与公平性，开发/验收工具）
- **标的范围**：A 股沪深主板 + 创业板 + 科创板；北交所不含
- **不涉及**：真实资金与支付；梯度类机器学习强化学习；量化回测；除权除息等公司行为处理（见 §7）

### 1.3 术语表

| 术语 | 含义 |
|------|------|
| 交易智能体（Trader Agent） | 系统级独立智能体实体：拥有独立模拟账户、当前生效版本的方法论、独立记忆库；每日执行「意图→盘中自主决策→复盘」循环 |
| 智能体类型 | 智能体的交易风格定位（首批：短线 / 中长线，枚举可扩展）：决定方法论提炼的知识域、风控护栏画像、唤醒时刻表、绩效对比分组 |
| 交易意图 | 智能体盘后生成的次日**意图边界**（非可执行脚本）：关注池、买卖意图区间、仓位边界、禁区（如不追高/不满仓）；盘中自主决策的约束框架与事后检讨的对照基准 |
| 唤醒（turn） | 智能体的一次完整 agentic 运行：输入增量盘面/电报/持仓/记忆上下文，按方法论思考，输出结构化决策（执行/持有/更新意图）；分**周期唤醒**（注意力时刻表）与**事件唤醒**（突发异动/快讯命中）两类 |
| 注意力时刻表 | 模拟人类交易员盘中注意力节奏的唤醒配置（按智能体画像可配）：开盘与尾盘高频、中段低频、午休不唤醒 |
| 记忆库 | 智能体的经验沉淀（按智能体隔离）：结构化经验条目（有效纪律/失效教训/市场观察），来源于复盘，注入盘中 turn 与学习任务 |
| 决策记录 | 每笔交易或观察结论的留痕（按智能体隔离）：类型（周期 turn/事件 turn/人工测试）、触发时点与行情上下文、决策理由、方法论条目/记忆/意图引用、关联委托；持有/观察类落轻量观察点 |
| 人工测试账户 | 管理员专用的独立模拟账户（不隶属任何智能体）：用于人工实际操作验证撮合引擎与公平性约束；数据与智能体严格隔离，不入学习闭环与绩效体系 |
| 强化学习 | 本需求语境：复盘反思 → 方法论/技能修订 → 版本沉淀 → 绩效验证的经验进化闭环（LLM 反思式学习），非梯度类机器学习强化学习 |
| 决策质量 | 学习信号口径：对照决策理由与当时盘面评估决策本身（纪律遵守、依据充分性），不以单笔盈亏为唯一标准 |
| 熔断 | 风控硬护栏：单账户当日回撤超阈值即停止开新仓（引擎逐 tick 兜底执行，不等唤醒点） |
| 公平性约束 | 保证智能体无法作弊的引擎级强制约束（时间因果、成交真实性、规则强制、资金守恒、频率护栏），见 §4.3 |
| 摊薄成本 | 持仓成本口径（与同花顺一致）：买入加摊、卖出盈亏调整成本；浮动盈亏 =（最新价 − 摊薄成本）× 持仓量 |
| 交割单 | 成交明细单据：成交价/数量/成交额/费用明细（佣金/印花税/过户费分列）/发生金额/成交后资金余额 |
| 净值曲线 | 每交易日收盘记录的账户总资产快照序列（按智能体独立）；收益率/回撤统计、版本与跨智能体绩效对比、学习信号的数据底座 |

| 知识库（F-KB，迭代 12 开发中） | 课程视频/书稿转结构化知识库，ES 检索底座 | **方法论的共享源头**：双智能体共用同一知识库；提炼任务按智能体类型限定检索范围（短线域/中长线域），F-KB 未就绪前保留手工录入通道 |

| 配色体系 | 全站红涨绿跌 scheme-aware（项目铁律） | 盈亏数字、B/S 标记、净值对比配色一律走 formatters scheme-aware helpers |

## 3. 用户场景

| 场景 | 描述 | 频次 |
|------|------|------|
| 初始建方法 | 管理员分别为两个智能体触发提炼任务：从知识库各自风格域生成方法论 V1 草稿 → 分别人工审核生效 | 一次性（大版本重做同流程） |
| 盘后复盘定次日意图 | 交易日收盘后，两个智能体各自复盘当日交易并生成次日交易意图（关注池/意图区间/仓位边界/禁区） | 每交易日 |
| 开盘高频决策 | 9:30-10:30 每 5 分钟唤醒：agent 看开盘博弈（含竞价结果回看），按方法论思考，决定执行/持有/更新意图 | 每交易日 |
| 尾盘高频决策 | 14:20-15:00 每 5 分钟唤醒：尾盘兑现/规避隔夜风险的博弈窗口 | 每交易日 |
| 中段低频巡视 | 10:30-11:30、13:00-14:20 每 30 分钟唤醒巡视，趋势期低频观察 | 每交易日 |
| 事件即时唤醒 | 盘中突发（持仓/观察池标的急拉急跌、逼近涨跌停、重大快讯命中）即时唤醒判断，不受时刻表限制、受每日限频约束 | 事件驱动 |
| 硬风控兜底 | 低频时段持仓急速跌破硬止损/账户回撤触熔断——引擎逐 tick 直接执行处置，不等下一个唤醒点 | 事件驱动 |
| 周度学习 | 每周各智能体综合复盘（含盘中观察点轨迹回放）：强化有效纪律、修正失效教训 → 各自方法论修订草稿 | 每周 |
| 审核生效 | 管理员查看某智能体的修订草稿 → 审批生效 / 驳回 / 编辑后生效 | 每周 |
| 日常观测 | 用户打开观测面板，切换智能体查看：净值曲线、持仓、今日意图、决策流水（含盘中观察点）、复盘总结 | 日常 |
| 风格对比 | 跨智能体对比视图：短线 vs 中长线的净值曲线叠加、胜率/回撤/决策质量/唤醒-动作率对照 | 每周 |
| K 线回看 | 个股日 K 上回看两个智能体的历史买卖点（标记可区分）与当时决策理由 | 每周 |
| 版本绩效对比 | 对比某智能体不同方法论版本生效区间的绩效与决策质量 | 阶段性 |
| 出错回滚 | 某智能体新版本连续表现劣化 → 管理员回滚该智能体到历史版本（不影响另一智能体） | 事件驱动 |
| 撮合引擎验收 | 开发阶段管理员在人工测试账户手动下市价/限价单，核对成交价裁定、费用勾稽、状态流转 | 开发/验收期 |
| 公平性验证 | 管理员人工尝试违规操作（涨停买入、T+1 当日卖出、超资金下单、超护栏频次）→ 全部被引擎拦截 | 开发/验收期 |

## 4. 总体设计

### 4.1 自学习交易闭环（多智能体）

```
        知识库（F-KB，双智能体共享：短线域知识 / 中长线域知识）
                        │ 按智能体类型限定检索 → LLM 提炼
           ┌────────────┴────────────┐
           ▼                         ▼
    短线智能体 · 账户 A          中长线智能体 · 账户 B
    （方法论版本/记忆库/意图/      （同左，全部独立隔离，
      决策/交割/复盘——独立）       共享的只有知识库与行情）
           │                         │
           ├────────────┬────────────┤
           ▼                         ▼
    人工测试账户（管理员专用：同一撮合引擎与规则链路，数据隔离不入学习/绩效）
           │
           └────────────┬────────────┘
                        ▼  每交易日循环（各智能体独立，共享调度进程、快照通道与撮合引擎）
        盘后：复盘当日（含盘中观察点轨迹）+ 生成次日交易意图
        次日盘中：周期唤醒 turn（注意力时刻表）+ 事件触发 turn（突发/快讯/风控）
                  每 turn：增量盘面 + 电报 + 持仓 + 记忆 → 按方法论思考
                          → 自主决策 执行 / 持有 / 更新意图
                  引擎逐 tick 兜底：硬止损 / 熔断 / 护栏（确定性代码，不等唤醒点）
                        │
                        ▼
        交易数据按智能体隔离落库（意图/决策/委托/成交/净值）
                        │
                        ▼  各自：每日记忆沉淀 + 每周综合学习
        各自方法论修订草稿（新版本）──人工审核──▶ 各自生效替换
                        │
                        ▼
        技能资产库（按智能体）：版本/对比/回滚   +   跨智能体绩效对比
```

- 智能体的「盘中在场」由**调度进程**承载（时刻表定时器 + tick 风控 + 事件路由）；智能体的「智能」通过被唤醒的有限个 deepagents turn 介入，每 turn 秒级完成、天然是审计单元
- 学习信号以决策质量为核心：决策记录 × 成交结果 × 当日盘面三方对照；智能体间数据严格隔离
- 人工测试账户与智能体账户走**同一撮合引擎、同一规则链路**——这是「约束引擎级强制」可被人工验证的前提

### 4.2 交易规则引擎（同花顺口径，费率与护栏可配）

| 规则 | 口径 |
|------|------|
| 交易时段 | 集合竞价（9:15-9:25 / 14:57-15:00）收单不撮合，竞价结果价出来后按该价撮合（限价不满足废单）；连续竞价（9:30-11:30 / 13:00-14:57）快照驱动即时撮合 |
| 市价单 | 按当前最新快照价全额成交（无逐笔/五档数据，不做部分成交） |
| 限价单 | 快照价满足（买：最新价 ≤ 限价；卖：最新价 ≥ 限价）时按不劣于限价的快照价成交；当日有效，收盘未成交自动废单 |
| 数量 | 买卖均须 100 股整数倍（一期不处理送转股，持仓恒为整手） |
| T+1 | 当日买入数量次一交易日可卖；卖出委托冻结可用数量 |
| 涨跌停 | 按前收盘价计算（主板 ±10%、ST ±5%、创业/科创 ±20%，新股无涨跌停期按市价撮合）；触及涨停禁买、跌停禁卖 |
| 停牌 | 停牌标的禁止新委托，存量委托保持待撮合，复牌后恢复 |
| 费用 | 佣金 0.025%（最低 5 元，双边）、印花税 0.05%（仅卖出）、过户费 0.001%（双边）——可配常量，全账户统一；逐笔计入交割单与资金流水 |
| 价格与金额 | 价格精度 0.01 元；金额计算四舍五入到分 |
| 资金约束 | 买单按「委托价 × 数量 + 费用预估」冻结资金（账户内）；卖单冻结持仓可用数量 |
| 成本口径 | 持仓摊薄成本；浮动盈亏 =（最新价 − 摊薄成本）× 持仓量 |
| 风控硬护栏 | **按智能体画像独立生效**（系统默认 + 智能体级覆盖，可配），独立于方法论：单标的仓位上限、总仓位上限、每日委托次数上限、单日回撤熔断、持仓硬止损；**熔断与硬止损由引擎逐 tick 兜底执行（确定性代码），不等智能体唤醒点**——类比人挂的条件单：agent 主导决策，引擎兜底资金安全；人工测试账户走系统默认画像 |

### 4.3 公平性与反作弊约束（引擎级强制，智能体无法绕过）

| 约束 | 口径 |
|------|------|
| 时间因果 | 智能体仅可引用**决策时点之前**的数据：每 turn 的行情上下文时间戳必须 ≤ turn 决策时刻；次日意图生成于 T 日盘后，允许使用 T 日及之前数据（合法前视，用于 T+1） |
| 成交真实性 | 成交价只能由撮合引擎按规则从真实快照价裁定，任何一方（含智能体、人工）无法指定成交价；不存在「按未来收盘价成交」通道 |
| 规则强制 | T+1 / 涨跌停 / 停牌 / 整手 / 资金约束 / 风控护栏全部在引擎层强制校验（含智能体下单工具内部），不依赖 prompt 遵守——智能体绕不过，人工同样绕不过（人工测试通道即验证手段） |
| 资金守恒 | 账户资金变动只能由撮合交割链路产生，资金流水逐笔勾稽；日终对账任务校验「可用+冻结+持仓成本 = 初始资金+累计已实现盈亏−费用」，不平即告警 |
| 频率护栏 | 每日委托次数上限、每日事件唤醒次数上限按画像强制；周期唤醒防堆积（上一 turn 未完成则跳过下一周期点，不并发不排队） |
| 留痕可查 | 决策、委托、成交、资金变动、每 turn 结论全量留痕且不可变，支持任意事后审计抽查 |

### 4.4 盘中注意力时刻表（按智能体画像可配；模拟人类交易员注意力节奏）

| 时段 | 唤醒节奏 | 说明 |
|------|----------|------|
| 9:15-9:25 竞价 | 竞价观察 turn ×2（9:22 / 9:25） | 竞价匹配价/未匹配量是短线核心信号；9:25 开盘价确定后出开盘评估 |
| 9:30-10:30 | 每 5 分钟（约 12 turn） | 开盘博弈最激烈，高频窗口 |
| 10:30-11:30 | 每 30 分钟（2 turn） | 趋势消化期，低频巡视 |
| 11:30-13:00 午休 | 不唤醒 | 休市；13:00 开盘恢复 |
| 13:00-14:20 | 每 30 分钟（约 2~3 turn） | 午后趋势期 |
| 14:20-15:00 | 每 5 分钟（约 8 turn） | 尾盘博弈（14:57 收盘竞价前为决策窗口） |
| 盘后 | 复盘 + 次日意图 turn ×1 | Celery internal 定时任务 |

- 单智能体每日约 26 个周期 turn + 事件 turn（限频）+ 盘后 1 turn；双智能体约 60 turn/日
- 事件触发**不受时刻表限制**：持仓/观察池标的急拉急跌、逼近涨跌停、重大快讯命中观察池 → 即时唤醒（每日次数上限按画像）
- 中长线智能体可将高频窗口拉长为每 15~30 分钟（画像差异的体现）

## 5. 功能需求

### 5.1 F-SIM-01 智能体与模拟账户

- **描述**：`trading_agent` 实体管理——首批种子两个：短线智能体、中长线智能体（各配独立模拟账户，初始 200,000 元虚拟资金）；管理员可创建新智能体（选择类型、命名、分配初始资金）、配置唤醒时刻表与护栏画像、启停（停用即停止交易循环，数据保留）；另有一个**人工测试账户**（初始 200,000 元，管理员专用）；资产总览按智能体展示：总资产、可用资金、持仓市值、冻结金额、当日盈亏、累计收益率
- **关键规则**：智能体与账户一对一，数据全域按智能体隔离；测试账户不隶属任何智能体（无方法论、无学习闭环、无绩效归因）；账户绑定当前生效方法论版本（绩效归因到版本）；重置 = 当前轮次归档 + 新开一轮（按账户独立操作），历史轮次保留可查；虚拟资金无任何支付属性

### 5.2 F-SIM-02 盘中实时快照通道

- **描述**：交易时段驻留进程按可配间隔（默认 10 秒，5~60 秒可配）对快照标的集批量拉取最新行情写 Redis；非交易时段自动休眠；竞价时段提供匹配价/未匹配量
- **关键规则**：快照标的集 = **全部活跃智能体**的关注池 ∪ 持仓标的 ∪ 待撮合委托标的 ∪ 人工测试账户持仓/委托标的（动态进出、去重），单批 ≤ 60 只；快照服务三个消费方：撮合裁定、tick 级硬风控、turn 上下文组装——不落分钟级历史库；腾讯主渠道失败退避切换新浪备选，连续失败纳入 F-MON 告警；交易日历/时段判定复用既有能力（调度北京时间、时间戳 aware UTC）

### 5.3 F-SIM-03 委托与撮合引擎

- **描述**：共享撮合引擎，按 §4.2 规则表快照驱动撮合，多智能体委托与人工测试委托在各自账户内独立核算；委托状态机：待撮合 → 已成 / 已撤 / 废单
- **关键规则**：下单校验链（账户/时段/停牌涨跌停/整手/资金持仓）+ 该智能体护栏画像校验——**校验在引擎层统一实现，智能体下单工具与人工测试委托走完全相同代码路径**；撮合与资金/持仓变更同事务、进程内串行；收盘未成交批量废单；服务重启后待撮合委托恢复续撮，无重复成交、无错账；除硬风控兜底与人工测试通道外无其它人工下单接口

### 5.4 F-SIM-04 持仓与估值

- **描述**：持仓按智能体展示（代码/名称、持仓量、可用量、摊薄成本、最新价、浮动盈亏与比例、市值），盈亏走 scheme-aware 红涨绿跌；最新价取快照通道（收盘后固定为收盘价）
- **关键规则**：持仓为零自动清行；停牌持仓按停牌前价估值并标注

### 5.5 F-SIM-05 交割单与资金流水

- **描述**：交割单按账户独立：逐笔列表（成交时间、标的、方向、成交价、数量、成交额、费用分列、发生金额、余额），支持区间筛选与 CSV 导出，区间汇总（总盈亏/手续费合计/笔数）；资金流水逐笔记录并关联成交
- **关键规则**：不可变记录（只查不改不删，重置归档不销毁）——复盘数据完整性底线；智能体交割数据与人工测试数据物理隔离；日终资金守恒对账（§4.3）异常告警

### 5.6 F-SIM-06 绩效统计与跨智能体对比

- **描述**：
  - **单智能体绩效**：净值曲线（叠加沪深 300 同期归一化对比）、胜率/盈亏比/最大回撤、平均持仓天数、分股已实现盈亏排行；按方法论版本切片对比各生效区间绩效
  - **跨智能体对比**：短线 vs 中长线净值曲线叠加、核心指标对照表（收益率/回撤/胜率/换手/持仓周期/唤醒-动作率）、风格差异一目了然
- **关键规则**：由 `paper_trade`/`paper_daily_nav` 派生计算（不另存宽表）；**人工测试账户不进入任何绩效统计与对比**；版本切片自二期有版本数据起生效；三期扩展决策质量维度（意图执行率、纪律遵守率、决策-结果对照），见 F-SIM-13

### 5.7 F-SIM-07 K 线买卖点标记

- **描述**：个股详情页日 K 叠加 B/S 只读标记：锚定成交日 bar、按成交价纵向定位、同日聚合计数角标；**标记按智能体区分**（色系/图标），支持按智能体筛选；点击标记弹出该笔成交明细与决策理由（含所属智能体与触发 turn 类型）
- **关键规则**：独立只读图层（复用 arch 09 图层隔离架构），与画线图层互不干扰、不可拖拽编辑；**人工测试账户成交不进 K 线标记**；一期仅日 K 展示（周/月聚合定位失真隐藏；分时标注后置）

### 5.8 F-SIM-08 观测面板

- **描述**：侧边栏顶层新增「模拟交易」入口（`/paper-trading`），登录用户可见；页面结构：智能体切换器 + 资产总览条 + Tabs（持仓 / 委托 / 交割单 / 统计；二期增「今日意图」「决策流水（含盘中观察点轨迹）」「复盘」；另有跨智能体对比视图）
- **关键规则**：观测面板对普通用户**只读且仅覆盖智能体数据**（测试账户不可见）；决策卡片是观测核心：每 turn 的时点、类型（周期/事件/兜底）、理由、依据引用（意图/方法论条目/记忆条目）、结果关联——让人「看懂智能体为什么这么做」；管理员身份下额外出现「人工测试」入口（F-SIM-14）

### 5.9 F-SIM-09 交易智能体运行时与记忆库（二期）

- **描述**：智能体运行时：每智能体一个 deepagents 实例（交易员身份 + 生效方法论 + 工具集组装进 instructions），PostgresCheckpointer 持久化（thread 按智能体+交易日滚动）；**调度进程**承载注意力时刻表定时器、tick 硬风控、事件路由，在事件点以 `ainvoke` 唤醒 turn；全部 LLM 调用走系统模型（系统维度计量，按智能体标注可对账）
- **关键规则**：
  - **turn 上下文组装**：自上次唤醒以来的盘面摘要（快照压缩）、当前持仓与盈亏、当日交易意图与已执行交易、活跃记忆、**财联社电报增量快讯**（命中关注池优先）
  - **turn 输出结构化**：动作（买入/卖出/撤单/持有/更新意图）+ 理由 + 意图更新；交易类落完整决策记录并走下单工具（过引擎校验），持有/观察类落轻量观察点——盘中注意力轨迹可回放、可学习
  - **防堆积**：同一智能体上一 turn 未完成则跳过下一周期唤醒点（不并发、不排队）；事件 turn 优先于周期 turn
  - 记忆库按智能体隔离（活跃 → 吸收进方法论 → 归档），注入每 turn 上下文（限条数防爆炸）；智能体停用后循环暂停、数据保留

### 5.10 F-SIM-10 每日交易循环（二期，按智能体独立执行）

- **描述**：每个活跃智能体的交易日循环，三段式：
  - **盘后复盘 + 次日意图**（收盘后定时任务）：LLM 复盘本智能体当日（意图执行对照、逐笔决策质量评估、盘中观察点轨迹回看、经验沉淀 → 记忆条目 + 复盘报告落库），随后生成**次日交易意图**——关注池、买卖意图区间、仓位边界、禁区（结构化 Schema 全 required）；意图是盘中自主决策的约束框架，**不是可执行脚本**
  - **盘中自主决策**：按注意力时刻表（§4.4）周期唤醒 + 事件触发唤醒；每 turn 实时看盘面/电报/持仓/记忆 → 按方法论思考 → 自主决定 执行交易（走下单工具）/ 持有不动 / 更新意图；决策记录全留痕
  - **引擎 tick 级兜底**：硬止损、熔断、护栏由调度进程逐 tick 检查执行（确定性代码），处置动作落决策记录（来源标记「硬风控兜底」）——资金安全不依赖 turn 节奏
- **关键规则**：
  - 周期与事件唤醒均受公平性约束（§4.3）与频率护栏约束；竞价阶段 turn 可看匹配价/未匹配量（9:25 开盘价确定后出开盘评估）
  - 故障降级：LLM 不可用时所有唤醒暂停开新仓，存量持仓仅由引擎硬止损/熔断兜底处置，并告警——智能体故障时资金安全不悬空
  - 预算护栏：按智能体计量，超限自动降频（拉长周期唤醒间隔）并告警

### 5.11 F-SIM-11 方法论提炼与知识库接线（二期）

- **描述**：按智能体类型分域提炼：管理员为某智能体触发提炼任务 → LLM 从共享知识库中**该类型知识域**（短线域/中长线域，按知识库分类/标签过滤检索）按固定框架（选股/买入/卖出/仓位/风控/执行纪律）生成结构化方法论草稿 → 管理员审核生效
- **关键规则**：知识库为两智能体共享的唯一知识源，提炼检索范围按智能体类型限定（不互相取材）；方法论以**规则条目级**结构化存储，可被意图与决策记录引用；依赖 F-KB 检索底座，未就绪时保留管理员手工录入通道；大版本重做走同一提炼-审核流程

### 5.12 F-SIM-12 学习迭代与经验强化（三期，按智能体独立）

- **描述**：
  - **每日增量**：盘后复盘直接沉淀本智能体记忆条目（有效纪律强化/失效教训/市场观察）
  - **每周综合学习**（定时任务，按智能体分别执行）：LLM 汇总本智能体本周复盘报告 + 记忆条目 + 盘中观察点轨迹 + 版本区间绩效 → 生成方法论修订草稿（版本号+1，状态待审）；草稿必附：修订点、理由、依据的复盘/绩效证据
- **关键规则**：各智能体学习完全独立（记忆、证据、产出互不混用）；学习输入**不含人工测试账户数据**；强化信号以决策质量为核心（好决策坏结果 / 坏决策好结果分辩、纪律遵守率、意图执行率、版本绩效对比），不以单笔盈亏论英雄；学习任务频次固定（周度综合为主，日度仅记忆沉淀），成本随智能体数线性可预期

### 5.13 F-SIM-13 方法论技能资产库与管理端治理（三期）

- **描述**：
  - **版本资产库（按智能体）**：版本列表、内容对比（条目级 diff）、生效历史与各区间绩效标注、意图/决策对条目的引用回查
  - **治理操作（限管理员）**：审批生效 / 驳回 / 编辑后生效（编辑产生新草稿版本，不覆盖历史）/ 回滚到历史版本 / 停用；全部治理操作入审计日志
  - **决策质量统计（按智能体）**：意图执行率、纪律遵守率、唤醒-动作率（多少 turn 转化为交易）、决策-结果对照分析（按版本区间）；跨智能体维度进入 F-SIM-06 对比视图
- **关键规则**：回滚即切换该智能体生效版本（新区间重新计量绩效，历史区间数据不删）；管理员可查看全部智能体的技能与记忆资产

### 5.14 F-SIM-14 人工测试交易通道（一期，管理员专用）

- **描述**：管理员专用的模拟盘人工操作能力，**开发与验收工具，非用户功能**：
  - **人工测试账户**：独立账户（初始 200,000 元），不隶属任何智能体，走与智能体完全相同的撮合引擎、交易规则与校验链路
  - **手动下单面板**（观测面板管理员身份可见的「人工测试」区）：标的搜索、市价/限价切换、数量整手步进、预估金额与费用、可用资金/可卖数量提示、委托列表与撤单、测试账户持仓与交割单——体验对齐常规交易面板
  - **委托来源标记**：人工测试委托标记 `manual`，与智能体委托（周期 turn/事件 turn/硬风控兜底）可区分
- **关键规则**：
  - **公平性验证**：人工尝试违规操作（涨停买入、跌停卖出、T+1 当日卖出、超资金下单、非整手、停牌标的、超护栏频次、指定成交价）必须被引擎以与智能体委托相同的方式拦截——证明约束为引擎级强制，智能体无作弊空间（§4.3）
  - **数据隔离**：测试账户数据不进入智能体学习闭环、绩效统计与对比、K 线买卖点标记、普通用户观测视图；仅管理员可见，全程带「测试」标识
  - 智能体上线后该通道保留，作为回归验收与行为对照工具；操作入审计日志

## 6. 非功能需求

| 项 | 要求 |
|----|------|
| 隔离性 | 智能体间及与人工测试账户间数据严格隔离，任何单账户故障、停用、回滚不影响其余；共享的只有知识库、行情快照与撮合引擎（引擎内账户独立核算） |
| 公平性 | §4.3 约束全部引擎级强制并有验收用例覆盖；日终资金守恒对账，不平即告警；决策时间因果可事后审计 |
| 决策时效 | 周期 turn 按时刻表准点唤醒（秒级偏差）；事件 turn 即时触发；硬风控逐 tick（≤ 快照周期）执行；单 turn 运行秒级~分钟级（不承诺 tick 级 LLM 延迟），turn 未完成则跳过下一周期点不堆积 |
| 成本护栏 | turn 数量有界且按智能体计：约 26 周期 turn + 事件 turn（限频）+ 盘后 1 turn，每 turn 为完整 agentic 运行按工具轮次计量；按智能体标注可对账；预算超限自动降频并告警；人工测试零 LLM 成本 |
| 资金安全 | 风控硬护栏按账户画像独立生效且逐 tick 兜底（熔断/硬止损/仓位/频次上限），独立于方法论与 turn 节奏；智能体故障时存量持仓有确定性降级处置并告警 |
| 数据一致性 | 撮合事务化、进程内串行、重启续撮、无重复成交/资金错账；多账户委托在同一串行队列内按账户独立核算 |
| 可审计 | 意图、决策（含观察点）、委托、成交、资金变动、治理与测试操作全量留痕；每笔成交可回溯到来源、turn 理由、意图条目与当时行情上下文 |
| 性能 | 观测面板查询 P95 < 500ms；统计实时派生（双智能体数据量级） |
| 时区 | 交易时段/时刻表判定北京时间；时间戳 aware UTC（项目铁律） |
| 数据 | 新表 12 张走幂等 SQL 迁移 + 同步 init-scripts；交割单/流水/决策记录不可变 |
| 兼容 | 快照/撮合/LLM 故障仅影响本域（页面明确提示、恢复自动续跑），不波及平台其它功能；F-MON 监控全覆盖 |

## 7. 功能边界

**包含**：多智能体虚拟交易训练场（共享撮合引擎 + 实时快照通道 + A 股规则引擎 + 按画像风控硬护栏（tick 级兜底）+ 公平性引擎级约束；首批短线、中长线两个智能体，架构支持 N 个）、各智能体独立的每日交易循环（盘后复盘与次日意图 / 盘中按注意力时刻表周期唤醒 + 事件唤醒的自主决策 / 记忆库）、按类型分域的方法论知识库提炼、各自学习迭代（日增量 + 周综合）、方法论版本资产库与管理端治理（审批/回滚/对比/审计）、观测面板（智能体切换 + 跨智能体对比）与 K 线多智能体 B/S 标记、管理员专用人工测试交易通道

**不包含**：面向普通用户的人工交易功能（人工操作仅限管理员测试通道，普通登录用户纯观测）；真实券商接口与真实资金（01 §6.2 边界不变）；梯度类机器学习强化学习（本需求「强化学习」为 LLM 反思式经验进化，§1.1 已澄清）；每 tick（秒级）LLM 决策（行业无此实践：噪声主导且成本不可控，自主决策粒度为分钟级 turn）；**智能体间数据互通或合谋**；量化回测/历史策略回放（与本闭环互为补充的另一类能力，如需另行立项）；除权除息/分红送股等公司行为处理（一期不做，跨除权长期持仓统计失真，二期评估）；逐笔/五档行情与部分成交模拟；北交所标的；更多智能体类型的接入流程产品化打磨与智能体间对战（后置，触发条件：双智能体闭环跑稳）

## 9. 验收对照

| 样本场景 | 预期结果 |
|----------|----------|
| 方法论 V1 提炼 | 分别为两智能体从各自类型知识域生成结构化草稿（六大纪律框架完整、条目级可引用）；审核生效后账户与意图可见各自版本；两智能体方法论互不相干 |
| 盘后复盘定次日意图 | 收盘后两智能体各自生成日复盘（含盘中观察点轨迹回看）+ 次日交易意图（关注池/意图区间/仓位边界/禁区）；观测面板可见 |
| 开盘高频 turn | 9:30-10:30 每 5 分钟准点唤醒，每 turn 带增量盘面/电报/持仓/记忆上下文，输出结构化决策并留痕 |
| 注意力时刻表 | 午休 11:30-13:00 无唤醒；10:30-11:30 与 13:00-14:20 低频唤醒；中长线画像频率低于短线画像；上一 turn 未完成时下一周期点跳过不堆积 |
| 事件即时唤醒 | 盘中突发（急拉急跌/逼近涨跌停/快讯命中关注池）即时唤醒判断并留痕；超过该智能体事件限频不再触发且留痕说明 |
| 意图非脚本 | 意图不被代码直接执行；盘中交易均出自 turn 决策且决策记录引用意图条目；agent 可输出「持有不动」 |
| 硬风控 tick 兜底 | 低频时段持仓急跌破硬止损/回撤触熔断，引擎在快照周期内直接处置并落「硬风控兜底」记录，不等唤醒点 |
| 多智能体隔离 | 两智能体同日交易同一标的时，账户、持仓、交割、决策完全独立无串数；一者停用/故障，另一者不受影响 |
| 故障降级 | LLM 不可用时所有智能体暂停开新仓、存量持仓仅由硬止损/熔断兜底处置并告警；快照中断恢复后自动续撮；平台其它功能零影响 |
| 成本护栏 | 每智能体 turn 数量与 LLM 用量按日可对账；预算超限自动降频并告警；人工测试零 LLM 消耗 |
| 周度学习 | 各智能体独立生成方法论修订草稿，附修订点/理由/复盘与绩效证据；不自动生效；证据不含另一智能体与测试账户数据 |
| 审核与回滚 | 审批生效替换该智能体当前版本；回滚切换历史版本且历史绩效区间保留；编辑草稿产生新版本不覆盖历史；治理操作全入审计日志 |
| 版本与风格对比 | 同一智能体各版本区间绩效可对比；跨智能体对比视图（净值叠加 + 指标对照含唤醒-动作率）可辨短线与中长线风格差异 |
| 记忆闭环 | 日复盘沉淀的经验条目出现在该智能体次日盘中的 turn 上下文引用中；被方法论吸收的条目状态流转正确 |
| 交割对账 | 各账户交割单逐笔费用与发生金额、资金余额勾稽一致；日终资金守恒对账通过 |
| K 线回看买卖点 | 两智能体历史成交在个股日 K 以可区分的 B/S 标记定位；支持按智能体筛选；点击标记可见所属智能体、turn 类型与决策理由 |
| 人工测试同链路 | 管理员在测试账户手动下市价/限价单，成交价裁定、费用勾稽、状态流转与智能体委托走同一引擎完全一致；撤单即时解冻 |
| 公平性人工验证 | 人工尝试涨停买入 / 跌停卖出 / T+1 当日卖出 / 超资金下单 / 非整手 / 停牌标的 / 超频次委托，全部被引擎拦截且拒因明确 |
| 测试数据隔离 | 人工测试成交不出现在智能体绩效、跨智能体对比、K 线标记、学习输入与普通用户视图；管理员视图全程带测试标识 |
| 时间因果审计 | 抽查任意 turn 决策记录：行情上下文时间戳 ≤ 决策时刻；次日意图仅引用 T 日及以前数据；无未来数据引用路径 |
| 观测纯度 | 普通登录用户仅可观测智能体数据、无任何交易入口；人工测试入口与治理功能仅管理员可见可用 |
