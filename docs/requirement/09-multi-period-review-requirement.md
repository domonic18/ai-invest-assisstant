## 1. 文档概述

### 1.1 背景与目的

交易 Agent 目前只有每日复盘：每日盘后对当天交易做分层归因。它能回答「今天做得对不对」，但回答不了「这套策略本身对不对、哪些做得好、哪些做得不足、哪些机会没把握住」。

日复盘的短视问题不是靠把日复盘写长能解决的——**评价周期本身决定了能看见什么**。因此需要在日复盘之外，增加站在更长维度的复盘（周 / 月 / 季 / 半年 / 年）：日复盘是执行层体检，长周期复盘是策略层体检，两者并行、互不替代。

**关键区分**：周期是「复盘内容的维度」，不是「触发复盘的行为」。选择年度视角不等于只在年末触发，随时可以要求一次年度视角的复盘。

### 1.2 适用范围与用户

- 面向用户：管理员（交易 Agent 观测页）、交易 Agent 自身（对话触发）
- 覆盖对象：交易 Agent 专属模拟盘账户（`trading_agent` 绑定的 `paper_trade_account`）
- 不涉及：人工测试账户复盘（维持现状：不做 LLM 复盘）；跨 Agent 横向对比；真实券商数据

### 1.3 术语表

| 术语 | 含义 |
|------|------|
| 复盘周期 | 报告的内容维度：日 / 周 / 月 / 季 / 半年 / 年 |
| 本期 | 当前周期首日至基准交易日（周期至今） |
| 上期 | 紧邻的上一**完整**周期 |
| 基准交易日 | 复盘窗口的结束日，必须为交易日 |
| 基准 | 用于超额收益对比的指数，定版为沪深 300（`sh000300`） |
| 触发 | 生成行为：自动（定时）/ 手动（页面）/ 对话（Agent 工具） |
| 专属板块 | 不同周期独有的报告章节（如季/年的收益归因） |
| 关键交易 | 系统确定性筛出的点评对象：盈亏 Top N、违规单、计划外单 |

## 2. 现状（2026-10-29 代码实证）

| 能力 | 现状 | 位置 |
|---|---|---|
| 周期枚举 | 仅 `day / week / month` | `services/trading/agent_review_content.py`、`api/v1/admin/trading_agent.py` |
| 窗口语义 | 一律「周期至今」：日=当日、周=周一→当日、月=1 号→当日 | `agent_review_service.resolve_window` |
| 输出契约 | 所有周期共用一套 schema，period 只是入参 | `PaperTradeReviewContent` |
| 提示词 | 所有周期共用 `skills/trading-default/review_prompt.yaml` | skills/ |
| 触发 | 定时 19:00（实例名 `paper_trade_review_1610`），按 `review_cadence` 门控；daily 在周期末加发周/月 | `collector/spiders/paper_trade_review.py` |
| 生成入口 | 仅定时生成；API 只读 | `GET /admin/trading-agents/{key}/review` |
| 输入数据 | 窗口内委托/成交/资金净值曲线 + 基准日大盘复盘 + KB 纪律 | `agent_review_inputs.py` |
| 缺失数据 | 无持仓快照、不关联交易计划、无 A 股基准指数 | — |

结论：本需求不是「加枚举值」，而是**窗口模型、输出契约、触发通道、数据底座**四方面同时演进。

## 3. 目标与非目标

**目标**

1. 六档周期：日 / 周 / 月 / 季 / 半年 / 年，各有独立的分析框架与专属板块；
2. 本期 / 上期快捷切换，支持任意自定义区间；
3. 周期与触发解耦：日/周/月自动，季/半年/年按需；
4. 任意两个窗口可按同一组指标对比；
5. 长周期具备可解释的收益归因（相对基准）。

**非目标**

- 不改变日复盘既有产物与调用方行为；
- 不做人工账户复盘、跨 Agent 对比、真实交易；
- 不做量化回测（本能力复盘的是已发生交易，不是策略回放）；
- 不引入新的 LLM 供应商或新的存储系统。

## 4. 功能需求

### 4.1 F-REV-01 周期档位与窗口

- **描述**：周期六档，报告基准日必须为交易日，窗口自动收边到交易日。
- **窗口规则**：

| 周期 | 本期 | 上期 |
|---|---|---|
| 日 | 基准交易日当日 | 上一交易日 |
| 周 | 本周一 → 基准日 | 上一完整 ISO 周 |
| 月 | 本月 1 日 → 基准日 | 上一自然月 |
| 季 | 本季首日 → 基准日 | 上一自然季 |
| 半年 | 本半年首日（1/1 或 7/1）→ 基准日 | 上一自然半年 |
| 年 | 1 月 1 日 → 基准日 | 上一自然年 |

- **关键规则**：周期仅决定内容维度，不决定触发时机；窗口内非交易日不参与统计；账户历史不足以覆盖窗口时照常生成，并在报告中标注实际覆盖区间与交易日数。

### 4.2 F-REV-02 报告结构（统一框架 + 专属板块）

- **描述**：所有周期共用一套外层框架，各周期追加专属章节。
- **统一块**：周期与窗口、整体结论、关键指标卡、关键交易点评、盘面语境、方法论验证、经验沉淀。
- **专属板块**：
  - 日：执行偏差（是否按计划执行、情绪化操作）
  - 周：短期节奏（追高 / 拖延 / 止损犹豫）+ 当周主线是否踩准
  - 月：策略有效性（选股与买卖点的胜率、盈亏比归因）
  - 季：收益归因（个股 / 行业贡献 + 相对基准超额）+ 体系评估（仓位、纪律、轮动）
  - 半年：策略迭代有效性（前后半段对比）+ 体系稳定性
  - 年：全年收益归因 + 长期能力评估 + 机会成本（错过的主线）
- **关键规则**：长周期不做全量逐笔；系统先确定性筛「关键交易」（盈亏 Top N、违规单、计划外单），其余只提供聚合数据；关键指标由系统计算，LLM 不得产出数值。

### 4.3 F-REV-03 时间选择

- **描述**：每档提供「本期 / 上期」快捷项；支持自定义起止日期。
- **映射规则**（自定义区间）：跨度 < 1 月→周框架；1–3 月→月框架；3–6 月→季框架；6–12 月→半年框架；> 12 月提示改用年档。起止自动对齐交易日。
- **关键规则**：自定义区间与快捷项生成同一份报告契约；缓存键包含周期与精确窗口，重复请求命中缓存。

### 4.4 F-REV-04 触发通道

- **描述**：
  - 自动：日（每交易日）、周（周期末交易日）、月（月末交易日），沿用现有定时任务；
  - 按需：季 / 半年 / 年不自动生成，由页面按钮或 Agent 对话触发；
  - 所有周期支持手动重跑（`regenerate`）。
- **关键规则**：按需生成异步执行，过程经 page_event 回写，完成后页面自动刷新；同一 Agent + 窗口并发生成由 redis 锁防重入；Agent 对话触发能力由工具提供，自然语言解析出的周期/区间映射到同一服务层入口。

### 4.5 F-REV-05 跨周期对比

- **描述**：选择任意两个已生成窗口，按**等长交易日**对齐，对比同一组指标。
- **指标集**（系统计算）：区间收益率、年化收益、最大回撤、胜率、盈亏比、换手率、执行偏差率、相对基准超额。
- **关键规则**：仅对比已完成生成的窗口；对齐按交易日条数截断，并标注可比性提示（市场环境不同不能直接等同于策略优劣）。

### 4.6 F-REV-06 经验沉淀

- **描述**：复盘提取的经验继续写入 `agent_memory`，反哺选股与计划。
- **关键规则**：长周期只沉淀**体系级**经验（method / discipline 的迭代结论），不重复日/周的微观条目；同标题经验不重复入库，由新结论覆盖旧结论。

## 5. 数据前提

| 项 | 要求 | 原因 |
|---|---|---|
| 每日持仓快照 | 新增 `paper_trade_position_snapshot`，盘后同步落库；历史由委托/成交重放重建 | 收益归因、期初/期末仓位分析 |
| 基准指数 | 沪深 300（`sh000300`）纳入指数 K 线跟踪并回填历史 | 超额收益与归因基准 |
| 交易计划关联 | 复盘输入 join `agent_trade_plan`（计划价、止损、目标价） | 「计划对错」不再靠成交价反推 |

## 6. 非功能需求

| 项 | 要求 |
|----|------|
| 成本 | 长周期不自动触发；单次生成输入规模有界（关键交易筛选 + 聚合指标），不随交易笔数线性膨胀 |
| 一致性 | 报告中的指标必须可由落库数据复算；LLM 仅解读 |
| 可用性 | 长周期生成失败不影响日/周/月既有产物；输入未就绪走重试，不落半成品 |
| 时区 | 窗口与交易日判定统一北京时间；时间戳 aware UTC |
| 兼容 | 现有日/周/月报告与页面在改造期间保持可用；旧缓存行必须可读 |
| 可审计 | 每次生成经 `AgentRunRecorder` 留痕（周期、窗口、触发方式、耗时、token 用量） |

## 7. 功能边界

**包含**：六档周期与窗口模型、统一框架 + 专属板块的报告契约、本期/上期/自定义区间、三种触发通道、跨窗口指标对比、持仓快照与基准接入、长周期经验沉淀规则。

**不包含**：人工账户复盘、跨 Agent 对比与排行、真实券商数据、策略回测与历史回放、自动调仓、对报告的编辑与批注、移动端适配。

## 9. 验收对照

| 样本场景 | 预期结果 |
|---|---|
| 六档切换 | 切换日/周/月/季/半年/年，报告同时呈现统一块与该周期专属板块 |
| 本期 vs 上期 | 一键切换，窗口正确收边到交易日，报告标注起止日期 |
| 自定义区间 | 输入 2026-09-01 至 2026-10-20，按**月框架**生成（跨度 1–3 月，§4.3 映射规则）；超出 1 年给出提示 |
| 触发解耦 | 选择年档不会触发额外定时任务；次日照常生成日复盘 |
| 按需生成 | 页面与对话均可触发季报，异步可见，完成后卡片自动出现 |
| 对比 | 选本月与上季度，等长交易日对齐，指标同屏且可复算 |
| 归因 | 季报给出个股/行业贡献与沪深300 超额，数值与快照数据一致 |
| 数据不足 | 账户仅 1 个月历史却请求年报，报告生成并标注实际覆盖区间 |
| 经验沉淀 | 长周期经验入库，同标题不重复；日/周经验不受影响 |
| 兼容 | 改造后既有日复盘内容与调用方可正常读取 |
