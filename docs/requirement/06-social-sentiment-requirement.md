# 社媒大 V 情绪追踪 需求文档

> 版本：V1.0（2026-09-13 定稿）　状态：待排期
> 本文档为独立需求，功能域编号 `F-SOC`；与既有设施（资讯中心 F-VIS-10、采集任务体系、AI 任务范式、04 知识库的 ASR 渠道、涨跌配色体系、F-MON 健康监测）的衔接在 §2 逐项说明，不改动既有需求文档
> 原型：[docs/prototypes/social-sentiment.html](../prototypes/social-sentiment.html)（情绪流 / 账号时间线 / 情绪温度 / 后台追踪管理四视图，2026-09-13）

## 1. 文档概述

### 1.1 背景与目的

交易中的情绪面分析，平台现有信源集中在**新闻电报、涨跌停统计、龙虎榜**等传统渠道，遗漏了当下影响力最大的两类社媒信源：

- **X（推特）推文**：政要与顶流大 V 的发言对市场有即时冲击（如特朗普的关税/政策推文），传播速度远快于新闻编排
- **抖音财经大 V 视频**：散户情绪的放大器，头部财经博主的明确看多/看空观点往往引领散户资金流向

本需求实现：对**平台指定的 X / 抖音账号**进行追踪，周期采集其新发内容（推文全文 / 视频转写文稿），由 LLM 判断每条内容的**多空立场、核心论点、影响标的**，并在**资讯中心新增「大 V 情绪」视图**，以直观友好的交互呈现——让用户一眼看到"谁在说、说了什么论点、看多还是看空、影响什么标的"。

### 1.2 适用范围与用户

- **追踪模式**：一期为**平台级**——管理员在后台统一配置追踪账号清单，全体登录用户看到同一份大 V 情绪视图；用户级自选订阅作为后置扩展预留（不阻塞架构）
- **覆盖平台**：X 与抖音（采集渠道按平台抽象设计，可扩展其他平台）；只追踪**指定账号**，不做全站热点扫描
- **面向用户**：管理员（配置与运营）、全体登录用户（浏览情绪视图）
- **不涉及**：视频画面/图像理解（一期仅音频转写 + 文本）；自动交易信号生成

### 1.3 术语表

| 术语 | 含义 |
|------|------|
| 追踪账号 | 平台级追踪清单中的一行：平台（x / douyin）+ 平台内唯一标识（handle / sec_uid）+ 显示别名 + 分类标签（宏观政策/财经大 V/产业人士等）+ 启用状态 |
| 社媒内容 | 追踪账号的新发内容单元：X 推文（含转推）或抖音视频（标题/文案/标签 + 音频转写文稿） |
| 情绪立场（stance） | LLM 对内容的多空判断：`bullish`（看多）/ `bearish`（看空）/ `neutral`（中性），附置信度与 `irrelevant`（与市场无关）标记 |
| 核心论点 | LLM 提炼的观点论据列表（每条一句话），呈现给用户"他为什么看多/看空" |
| 影响标的（targets） | 内容关联的市场对象：大盘指数 / 行业板块 / 个股（给代码）/ 大宗商品 / 加密资产 |
| 内容获取渠道 | 采集执行方抽象：X 渠道（官方 API 或第三方接口，后台可配可切换）、抖音渠道 |

## 4. 总体设计（采集 → 判断 → 呈现流水线）

```
管理员登记追踪账号（平台级清单，后台「社媒追踪」）
   │
   ├─ X 账号 ──X 采集任务（渠道抽象：官方 API / 第三方接口可配切换）──▶ 新推文（正文/发布时间/互动数据/原文链接）
   │
   └─ 抖音账号 ──抖音采集任务──▶ 新视频（标题/文案/话题标签/互动数据/音频）
                                       │ 音频 → 云端 ASR 转写（复用 04 ASR 渠道）
                                       ▼
                    社媒情绪判断任务（internal AI，仅增量内容）
                    LLM 结构化输出：relevance / stance+置信度 / 核心论点 / 影响标的 / 一句话摘要
                                       │
                                       ▼
                    social_account · social_post · social_sentiment 落库
                                       │
                                       ▼
                    资讯中心「大 V 情绪」视图
                    情绪流（立场徽标+论点卡+标的 chips）· 账号时间线 · 情绪温度（P2）
```

- 采集与判断均为 collector 任务（X/抖音采集走 external 渠道、判断走 internal 渠道），复用 runner 统一日志、手动补跑与 F-MON 监测
- 判断只对**增量**内容执行（采集侧按内容 ID 去重），成本可控

## 5. 功能需求

### 5.1 F-SOC-01 追踪账号与渠道管理（后台）

- **描述**：后台「社媒追踪」页。账号清单 CRUD：平台、平台唯一标识（X handle / 抖音 sec_uid）、显示别名、分类标签、启用状态、备注；渠道配置：X 获取渠道（官方 API / 第三方接口，endpoint、密钥加密存储、配额参数）与抖音采集参数，均可在后台切换启停
- **关键规则**：
  - 同平台同标识唯一，重复登记拒绝；账号失效（注销/改名/长期无更新）可标记停用并提示管理员
  - X 渠道为**抽象接口**：拉取某账号增量内容的统一契约，官方 API 与第三方各自实现，后台切换不改动任务定义；渠道配额/频控可配
  - 采集渠道密钥复用系统加密实践（AES-256-GCM、脱敏展示、日志过滤）
  - 删除追踪账号即停止采集（历史数据保留，视图可按需隐藏）

### 5.2 F-SOC-02 X 发文采集

- **描述**：轮询任务按账号周期拉取新推文：正文文本、发布时间、媒体数量、互动数据（点赞/转发/浏览，渠道给多少取多少）、原文链接；转推与原创同等入库
- **关键规则**：
  - 默认轮询间隔 15–30 分钟/账号（按账号可配）；渠道配额感知：接近配额上限自动降频并告警（入 F-MON），配额耗尽暂停该渠道而非失败重试烧配额
  - 内容按平台内容 ID 去重（编辑过的推文更新不重复判断）
  - 空窗与异常区分：账号长时间无新内容为正常态（SKIPPED），渠道不可用为故障（FAILED），不混淆

### 5.3 F-SOC-03 抖音视频采集与转写

- **描述**：轮询任务检测账号新视频，采集标题、文案、话题标签、发布时间、互动数据（赞/评/转）、音频；音频经云端 ASR 转写为全文文稿（复用 04 知识库文档定义的 ASR 渠道配置与用量对账机制）
- **关键规则**：
  - 默认轮询间隔 1 小时/账号（可配）；仅处理**新视频**（视频 ID 去重）
  - 转写为判断的输入而非展示物：视图呈现分析结论与摘要，不存储、不分发视频原片与完整文稿镜像
  - ASR 金融热词表注入（与 04 共用一份热词配置），降低口播术语错转率
  - 音频获取失败时降级为「仅文案判断」并标注 `transcript_missing`（不阻塞流程）

### 5.4 F-SOC-04 社媒情绪判断（internal AI 任务）

- **描述**：对增量社媒内容执行 LLM 结构化判断，输出：
  - `relevance`：市场相关 / 无关（大 V 发生活、广告内容标无关，不入情绪流）
  - `stance`：bullish / bearish / neutral + `confidence`
  - `core_arguments`：核心论点列表（每条一句话，保留博主表达的观点内核）
  - `targets`：影响标的（类型：index/sector/stock/commodity/crypto + 名称，个股尽量给代码）
  - `summary`：一句话摘要
- **关键规则**：
  - Schema 字段**全 required、禁带默认值**（项目铁律，钉死在单测）
  - 判断结果按内容 ID 缓存，同一内容不重复消耗 LLM；内容更新（推文编辑）视为新内容重判
  - 判断失败不阻塞采集（内容保留、标记待判，任务退避重试——对齐"输入未就绪退避"既有模式）
  - 时效窗口：超过 N 小时未判断的积压内容批量补判（手动触发）

### 5.5 F-SOC-05 资讯中心「大 V 情绪」视图

- **描述**：资讯中心新增第四 Tab，三层结构：
  - **情绪流**（默认视图）：最新已判断内容按时间倒序的卡片流——头像/别名/平台徽标（X/抖音）/发布时间/一句话摘要/**核心论点列表**/**立场徽标**（看多/看空/中性，走全站 scheme-aware 红涨绿跌配色）/影响标的 chips（点击跳板块监测或个股详情页）/互动数据/原文外链（跳原平台）
  - **账号维度**：按账号分组入口，进入单账号时间线，展示其近期立场轨迹（连续看多/转向）与最新观点
  - **情绪温度**（P2）：按分类聚合的净多空概览（如"宏观政策类：近 24h 看多 5 / 看空 2"），可视化温度条
- **交互规则**：
  - 过滤器：平台、分类标签、立场、时间范围；高置信度 + 高互动的内容卡片加重/置顶标记
  - 卡片展开显示完整论点；无关（irrelevant）内容不进入情绪流
  - 视图数据只读派生自 `social_*` 表，渠道故障时该 Tab 显示"部分渠道采集中断"提示，不影响资讯中心其余视图
- **可用端**：Web 端

### 5.6 F-SOC-06 情绪聚合与高冲击提醒（P2）

- **描述**：大 V 情绪指数（全量/按分类的净多空分值时序，接入工作台卡片）；高冲击提醒——高置信度立场 + 互动量异常放大的内容触发站内提醒（复用资讯重要度分级的通知通道）
- **价值**：从"被动浏览"升级为"主动触达"，覆盖盘中突发发言

## 6. 非功能需求

| 项 | 要求 |
|----|------|
| 权限 | 追踪清单与渠道配置限 admin；大 V 情绪视图全体登录用户可见 |
| 时效 | X 新推文默认 ≤30 分钟内完成采集+判断；抖音新视频默认 ≤1 小时；高互动突发不额外加速（依赖既有轮询节奏） |
| 成本 | ASR 与 LLM 用量逐任务记入 metadata 可对账；仅增量内容触发判断；X 渠道配额自适应降频防超额 |
| 合规 | 不存储/分发视频原片与完整文稿镜像，展示分析结论+摘要+原文外链；内容版权归原平台与作者；分析结论标注"AI 生成，非投资建议" |
| 可用性 | 社媒渠道故障不影响资讯中心其他视图与既有采集；新任务全部纳入 F-MON 健康监测与告警 |
| 时区 | 采集调度北京时间；时间戳 aware UTC；展示按用户本地化（dayjs，不硬编码时区） |
| 数据 | 新表 `social_account` / `social_post` / `social_sentiment`（幂等 SQL 迁移规范，同步 init-scripts） |

## 7. 功能边界

**包含**：平台级追踪账号管理、X/抖音采集渠道（X 渠道抽象可切换）、抖音音频 ASR 转写、LLM 多空/论点/标的判断、资讯中心「大 V 情绪」视图、（P2）情绪指数与高冲击提醒
**不包含**：用户级自选订阅（后置扩展预留）；微博/雪球/YouTube 等其他平台（架构按平台可扩展，接入另行立项）；视频画面与图像理解；评论区情绪抓取；自动交易信号；X 官方 API 的商务采购决策（渠道抽象就位后排期时定）
