# 交易日历管理（需求记录与分析）

> 状态：D1-D5 已拍板（2026-09-26），实现中。
> 来源：2026-09-26 用户口头需求——节假日（中秋/国庆/元旦等）系统仍按"周一~周五"触发 K 线、涨停等采集，拿不到数据白白浪费采集工作；希望在后台管理中清晰管理非交易日。

## 1. 背景与问题

- 节假日为工作日时，celery beat 的 cron（seed 全部 `* * 1-5`，只认星期掩码）照常触发采集任务。
- 盘中高频任务（sina_quote 5 分钟级、index-spot、auction、market-breadth 等）在节假日全天空转，产生空采/失败日志。
- 盘后任务（日 K、涨停池、资金流、龙虎榜等）触发后发出无效网络请求；部分任务靠 `latest_trading_day()` 落回上一交易日不致空采，但往返本身是浪费。
- AI 复盘链在节假日反复 `ReviewInputDataNotReadyError` 退避重试，全天空转。
- 当前拿不到数据不会误生成 AI 复盘，无正确性问题，纯粹是无效功与日志噪音。

## 2. 现状梳理（三 条互有盲区的线）

### 2.1 调度层：cron 只认周一~周五
`collector_task.schedule` / seed（03-seed.sql）全部为 `* * 1-5`。节假日（多为工作日）必然触发，调度层没有任何节假日概念。

### 2.2 采集侧：`collector/core/calendar.py`（新浪日历）
- `is_trading_day()` / `latest_trading_day()`：akshare 新浪 `tool_trade_date_hist_sina` 全量日历，进程内缓存每日刷新。
- **盲区**：网络失败或超出日历范围时回退"周一~周五启发式"——恰好退化为用户感知的"写死周末"；节假日误判风险由数据源空结果兜底（浪费已经发生）。
- 消费者：各 spider 的日期参数缺省值；`stock_anomaly` 等已有显式 `is_trading_day` 跳过（SKIPPED 良性终态）。

### 2.3 应用侧：`app/services/market/trade_calendar_service.py`（指数日 K 为权威）
- `is_trading_day`：先排除周末，再用上证指数日 K 是否有 bar 判定；**日 K 未覆盖的近期工作日直接放行为交易日**——代码注释自认"无权威节假日日历"的已知近似，节假日复盘页呈空态而非归位上一交易日。
- 被指数行情/涨跌统计/涨停池/板块/自选股/补采/AI 复盘/涨停归因共同依赖。

**核心矛盾**：两条判定线数据源不同、口径不同，且都没有一个可人工管理的权威节假日真相源。

## 3. 需求目标

1. 建立**单一真相源**的 A 股交易日历，节假日判定准确且可人工干预。
2. **后台管理**可视化管理：查看（月历）、调整（单日标节假日/调休上班）、初始化（整年批量）。
3. 调度与采集**非交易日不空转**：触发前预检跳过，不再产生无效网络请求与失败日志。
4. 应用侧（复盘缺省日等）与采集侧共用同一日历口径，消除"两套判定"。

## 4. 方案草案（待拍板后细化）

```
权威日历单一真相源（DB 表 + 进程内缓存）
        │
        ├── 调度预检：runner.run_task 统一入口先查日历，非交易日 → SKIPPED（不出网络）
        ├── 采集侧 calendar.py：改读 DB 日历（新浪/akshare 降级为初始化种子）
        └── 应用侧 trade_calendar_service：is_trading_day 改读 DB 日历（指数日 K 只作旁证）
```

### 已拍板决策（2026-09-26）

| # | 决策 | 定稿 |
|---|------|------|
| D1 | 权威数据源 | **① 新浪 akshare 日历做种子 + 后台人工覆盖**——复用 `calendar.py` 已验证的取数路径，零新增依赖；人工只做例外纠偏 |
| D2 | 表设计 | **单表 `market_trade_calendar`**：`calendar_date DATE PK / is_trading BOOL / source ('seed'\|'manual') / remark / created_at / updated_at`；来源标记便于审计 |
| D3 | 跳过生效点 | **runner 统一预检 + 任务级开关**：`collector_task.trade_day_only`（默认 false，种子对行情类任务置 true）；显式传 `trade_date` 参数的手动补跑不预检跳过（保留周末手动补跑能力） |
| D4 | 后台界面 | **月历视图**（antd Calendar，交易日/节假日着色）+ 单日点击切换（限今天及未来，防历史口径篡改）+ 「重新生成日历」按钮 |
| D5 | 日历缺失兜底 | **拒绝调度并告警**：`trade_day_only` 任务当日无日历覆盖 → SKIPPED（message 注明日历缺失），系统状态页可见；不静默回退周末启发 |

## 5. 影响面清单

- 后端：`collector/core/calendar.py`、`app/services/market/trade_calendar_service.py`、`runtime/runner.py`（预检）、新 admin CRUD + 迁移、seed 初始化任务（每年底生成下一年日历）。
- 前端：后台管理新增「交易日历」页（月历组件可复用投资日历的 antd Calendar 形态）。
- 不动：数据源 spider 本身、AI 复盘生成逻辑（输入检查自然受益）。

## 6. 验收标准

1. 节假日（如中秋）：全天无空采日志，runner 预检产生 SKIPPED（message 注明非交易日），AI 复盘不再退避空转。
2. 后台月历可正确展示当年交易日/节假日，单日调整后 1 分钟内生效（缓存失效策略明确）。
3. 调休上班的周六（如国庆补班）不被误判为交易日（现有周末启发式的主要反例）。
4. 复盘页在节假日自动归位上一交易日（消除已知近似）。
5. 单测覆盖：日历服务口径、runner 预检、admin CRUD 边界（过去日不可改为交易日等）。
